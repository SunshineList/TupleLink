# Daed 软路由插件

支持 OpenWrt、ImmortalWrt、iStoreOS 的现代 LuCI，提供 x86_64 / ARM64 的
IPK 和 APK v3 安装包。当前测试版：[openwrt-v0.6.13](https://github.com/slobys/daed/releases/tag/openwrt-v0.6.13)。

## 0.6.13 稳定性与社区入口

- 订阅下载支持取消；同一订阅的手动与定时更新串行执行，下载后重新核对订阅，拒绝已删除或修改链接的过期响应。提交失败正确返回错误，保留原数据。
- 清理已删除节点的测试缓存，按查询范围复制结果；切换页面时取消概况与测试结果请求，隐藏页面暂停结果轮询。
- 安装、卸载和服务操作共用内核文件锁，阻止并行操作相互干扰；源码安装器默认版本与发行版保持一致。
- 四个菜单均提供 YouTube / Telegram 入口，服务未启动时也可访问。重写项目首页说明，保留上游致谢与许可证。
- 无新增依赖、无数据库迁移。机场 SS / AnyTLS 可用性不在本轮修改范围。

## 0.6.12 无响应 SS 测试取消修复

- 修复 SS 服务器只接受 TCP、一直不返回加密数据时，HTTP 取消等待读取锁，导致单项或批量测试无法结束的问题。关闭测试/健康检查连接前先中断读写，及时释放连接及测试名额。
- 两轮各八个无响应 SS 的真实套接字回归覆盖超时返回及并发名额释放；正常协议传输和 HTTP 连接复用不改变。
- 此修复解决测试卡住，不会使其他客户端也无法连接的公网节点恢复。升级保留节点、订阅、群组和配置，无新依赖或数据库迁移。

## 0.6.10 运行概况流量修复

- 修复代理可正常联网、连接数有值，但速度、累计流量和趋势始终为零的问题：面板改为读取当前代理实例的统计，停止读取已废弃的全局计数器。
- 未启动代理时返回空统计；切换图表时间范围不会重置累计流量。重启代理或应用配置建立新实例后，从新实例重新累计。
- 增加真实 TCP 双向传输、UDP 回包、图表采样和实例切换回归。测试专用夹具不进入发行程序，也不会加载宿主 eBPF。
- 无前端布局变更、新依赖或数据库迁移，保留节点、订阅、群组、配置和偏好。

## 使用

安装后进入 **服务 → Daed**，默认显示管理面板：

- **管理面板**：上传、下载、连接及流量，群组创建、成员管理和代理启停。
- **节点和订阅**：手动节点、订阅及各订阅节点的独立管理。
- **高级设置**：配置、DNS 和路由。
- **运行日志**：自动刷新最近日志，保留大小限制与凭据遮盖。

隐藏首次向导、接口地址输入、注册登录和账户菜单；顶部保留主题、社区入口及代理操作。
浏览器沿用当前 LuCI 登录，不需要另设一套密码。HTTP 和 HTTPS 后台都通过同源
CGI 网关内嵌面板，不再要求新窗口。管理服务未运行时，面板提供启动按钮。

管理程序仅监听 `127.0.0.1`，默认内部端口 2023。浏览器从 LuCI 入口访问。
节点、订阅和路由仍需按实际网络配置；进入管理面板不等于已启用透明代理。

## 安装和保留数据升级

以 root 在路由器 SSH 中执行，已有本项目安装时使用同一条命令升级，无需卸载：

```sh
uclient-fetch -O /tmp/daed-install.sh https://github.com/slobys/daed/releases/download/openwrt-v0.6.13/install.sh && sh /tmp/daed-install.sh --release openwrt-v0.6.13
```

升级先停止 Daed 并等待进程退出，将配置、SQLite 数据库及 WAL 备份到
`/root/daed-backups`，然后更新程序；保留既有节点、规则、账户数据和自启选择。
新入口复用原用户的面板存储；没有用户时自动准备本地服务身份。
不需要删除旧版或重新建立账户。失败时提示备份位置，不自动回滚。

修改群组、节点或高级配置后，按顶部“应用配置”使其生效；该操作可能启动代理。
代理状态取自后端；管理面板的流量指标、趋势和累计数据默认直接展示。

升级后刷新后台，再进入 **服务 → Daed**；仍显示旧内容时按 `Ctrl+F5`。
无需修改监听地址。保留旧数据及原有排序、配色偏好，不重建数据库。

`--check` 仅检查环境；`--dry-run` 另下载并核对本机安装包，APK 使用已有
软件源索引模拟依赖。预检失败不会停止或卸载现有 Daed。正式安装会先更新
固件自身的索引。APK 不使用离线参数屏蔽未缓存的远端依赖，不强制忽略内核 ABI。

## 卸载和清空重装

```sh
# 安装成功后无需重新下载脚本
daed-router-setup --uninstall
# 也可以使用下载的脚本
sh /tmp/daed-install.sh --uninstall
# 仅在需要清空旧配置、或替换其他来源的 daed 包时使用
sh /tmp/daed-install.sh --reinstall
```

卸载、全新重装会先备份配置、数据库及 WAL，再移除 Daed 包和原数据。
`--reinstall` 不自动导入备份，原账户、节点和规则需要重新配置。
单独卸载不依赖 BTF、LuCI 或网络，支持 `--uninstall --dry-run` 和重复执行。
APK 会保留已经安装的 BTF、相关内核模块及必要依赖，避免被自动当作孤立依赖移除。
备份可能包含密钥，目录权限 0700、归档权限 0600。

## 规则库路径修复

0.3.2 修复点击启动代理时找不到 `geosite.dat` / `geoip.dat` 的问题。固件提供的
`v2ray-geosite`、`v2ray-geoip` 将文件装在 `/usr/share/v2ray/`，而 Daed 默认
搜索 `/usr/share/daed/`。运行包现在管理两条相对符号链接：

- `/usr/share/daed/geosite.dat` → `../v2ray/geosite.dat`
- `/usr/share/daed/geoip.dat` → `../v2ray/geoip.dat`

不复制规则库，不改动其他代理使用的文件。升级固件规则包时链接继续生效。
已有 `/etc/daed/` 自定义规则保持更高优先级。安装器完成安装后检查规则文件
可读性；只读预检在规则缺失时提示警告，允许首次安装补齐固件依赖。

若规则依赖本身损坏或缺失，请通过当前固件的软件源修复 `v2ray-geosite` 和
`v2ray-geoip`，不要用空文件代替。卸载运行包会移除这两条链接，保留共享规则库。

## 订阅通过本机 PassWall 出口下载

0.3.1 默认使用自动模式：先尝试原来的系统路径与 dae 路由；失败后，读取已运行
PassWall 的本机 SOCKS 出口再尝试下载。端口每次动态读取，不固定为 1070，
仅接受回环地址。下载域名交给 SOCKS 出口解析，继续校验 HTTPS 证书。
新增订阅、手动更新和定时更新使用相同逻辑，不修改订阅链接、节点或数据库结构。

升级后无需额外设置；原配置缺少 `subscription_proxy` 时也按 `auto` 处理。
对于“系统路径 AUTH_FAIL、PassWall SOCKS 成功”的订阅，添加/更新时保持
PassWall 正常运行。它借用现有可用出口，无法使未获服务商授权的出口自动获得权限。
没有 PassWall 时，原有可用下载路径仍正常使用；下载失败不会删除已有节点。

可选的全局下载策略（立即对后续下载生效，无需重启）：

```sh
# auto：系统路径、dae 路由失败后尝试 PassWall（默认）
# passwall：仅用 PassWall SOCKS，失败时不切换出口
# off：只使用原有系统路径和 dae 路由
uci set daed.main.subscription_proxy='auto'
uci commit daed
```

不会启动、停止或修改 PassWall，也不会接管其他应用的下载。错误只报告状态和
已知 `AUTH_FAIL` 代码，不输出订阅 URL、服务商响应正文或 cookie。

## 订阅下载诊断

出现 403 时，先确认订阅在其他客户端的本次更新是否成功，区分已有节点可用
与订阅可下载。Daed 报错中的 `route` 是 dae 路由下载，不代表使用 PassWall。

仓库提供独立的只读工具 `openwrt/subscription-check.sh`，可用 `sh` 执行。
它读取最多 3 条 PassWall 订阅，分别测试系统路径的 Daed 请求头、PassWall
请求头/会话，以及可用的本机 PassWall SOCKS 出口；也可传一个命名订阅 section ID。
系统路径仍可能受透明代理规则影响，curl 测试不等同于 Daed 的 Go 下载客户端。

输出仅含 section ID、URL 的 SHA-256 指纹、HTTP 状态、curl 返回码、已知鉴权
错误代码及内容格式/节点链接数。节点链接数不证明协议参数可导入；HTML、Clash
YAML 和鉴权响应会单独标识。临时响应和 cookie 使用私有目录，结束后清理。
该工具不新增依赖，不修改订阅、服务、路由或防火墙配置，不关闭 TLS 校验。

只有系统路径失败、本机 SOCKS 成功时，才进一步核对两条下载路径的出口与权限。
`AUTH_FAIL` 表示订阅服务拒绝鉴权，需要结合服务商错误说明处理，不能仅靠状态码
认定是 User-Agent 问题。

## 已启动但无法访问的只读诊断

`openwrt/network-check.sh` 收集实际 LAN/WAN 设备、默认路由、现有 TC 过滤器、
代理服务状态、本机 DNS、国内/Google 的 IPv4 HTTPS 和 Google IPv6 HTTPS，
并在探测前后分别读取服务状态和已遮盖凭据的日志。不修改 UCI、数据库、路由、
防火墙或服务，不安装缺少的工具；DNS/HTTPS 请求有时限，仍经过当前透明代理路径。

v2 将 procd 未报告实例标为 `unreported`，查询失败标为 `unavailable`，不据此
判断代理已停止；额外报告常见代理核心进程是否存在及 nftables/iptables 中的
PassWall/OpenClash 文本标记数量，不输出进程参数或防火墙规则内容。这些标记
可能残留，核心也可能由不同插件使用，因此 `traffic_owner` 始终为 `unknown`。
HTTPS 成功只能说明当前路径可用，使用 PassWall 时的成功不代表 Daed 转发成功。

历史日志在探测前单独显示。探测后按两次日志快照的重叠部分识别新增行；日志
轮转或重置后无法确认连续性时标为 `log_continuity=unknown`，不将历史行冒充
本次探测日志。新增日志也可能来自后台流量，不能单独证明探测经过 Daed。
排查 Daed 时需在明确停止其他代理、从面板启用 Daed 后采集；测试结束若仍不通，
先在面板停止 Daed，再恢复原有代理，不要让两套透明代理同时接管网络。

`Ready`、群组选择节点和 eBPF 加载成功不能单独证明代理出口可用。启动时空
配置的 `[direct]` 不代表重载后的最终路由。Netkit 回退 veth 后继续成功启动时，
应先核对真实绑定和实际连接结果，避免仅根据该回退提示更换 iproute2。

## 环境要求

- 固件提供现代 JavaScript LuCI、uhttpd CGI、rpcd、UCI、jshn 和 jsonfilter。
- Linux 5.17+，具备 dae 所需 BPF 功能。支持原生 BTF 或加载器固定搜索路径中
  对应当前内核的外部 BTF/vmlinux，随包解析器核验格式、ELF 架构和网络类型。
- 固件自身软件源能够提供匹配本机内核 ABI 的 `kmod-sched-core`、
  `kmod-sched-bpf`、`kmod-veth` 及 `ca-bundle`、`v2ray-geoip`、`v2ray-geosite`。
- 足够的临时下载空间和 overlay 存储。APK 格式要求 apk-tools 3.x。

安装器不刷固件、不替换 BTF、不修改其他代理、DNS 或防火墙。
ARM64 架构标签以 `sdk-matrix.json` 为准，程序使用 ARMv8 基线。APK 按
`/etc/apk/arch` 选择标签，仅在列表缺失或为空时退回编译默认值。
系统名称、BTF 检查或管理页面启动不构成实际代理兼容性证明。

## 登录集成

CGI 网关通过 rpcd 校验当前 LuCI 会话对 `luci-app-daed-router` 的管理权限，
每个请求均重新校验，退出或过期的会话不能继续调用管理 API。
会话交接使用同源 POST，cookie 设置 HttpOnly / SameSite=Strict，并在 HTTPS 下
设置 Secure。写请求检查 Origin；不在 URL、页面或浏览器存储中下发 Daed JWT。

网关复用 wing 现有 SQLite 和 JWT 库生成短时本地授权，保持 wing 子模块固定提交，
不新增 npm 或 Go 依赖。私有服务凭据保存在 `/etc/daed/luci-session.json`，权限
0600。首次启动前准备身份，之后 CGI 不直接读写数据库。
只读 LuCI 账户可看日志，管理面板需要该 ACL 组的写权限。

## 开发

```sh
# 在已有工作区依赖构建后，生成路由器专用前端
pnpm --dir apps/web build:openwrt
# 应用主仓库中可审查的订阅下载补丁；子模块提交不变
python3 openwrt/prepare-wing.py wing
# 使用独立输出目录，避免工作区测试/普通网页版构建覆盖路由器前端
CGO_ENABLED=0 make -C wing APPNAME=daed VERSION=0.3.2 WEB_DIST="$PWD/apps/web/dist-openwrt" OUTPUT="$PWD/daed" bundle
# 从 wing/ 构建，复用已锁定的 Go 依赖
(cd wing && CGO_ENABLED=0 go build -trimpath -ldflags='-s -w' -o ../btf-probe ../openwrt/btf-probe.go)
(cd wing && CGO_ENABLED=0 go build -trimpath -ldflags='-s -w' -o ../luci-proxy ../openwrt/luci-proxy.go)
python3 openwrt/build.py --target ipk-x86_64 --binary ./daed --btf-probe ./btf-probe --luci-proxy ./luci-proxy --version 0.3.2 --work /path/to/sdk-cache --output /path/to/packages
python3 openwrt/manifest.py /path/to/packages --version 0.3.2
node --test tests/openwrt/ui.test.cjs
```

订阅下载增量源码位于 `openwrt/wing/`，准备工具核对固定上游源文件哈希，
拒绝覆盖未知修改，并支持重复执行。源码归档同时包含这些文件与原始子模块；
构建前执行上述准备命令即可复现，不依赖未推送的子模块提交。

其余 SDK 目标：`ipk-arm64`、`apk-x86_64`、`apk-arm64`。SDK URL、哈希和
feed 提交固定在 `sdk-matrix.json`，原生打包后逐一验证文件、架构和权限。
手动工作流生成 artifact，测试版仍需维护者核验并发布为 prerelease。

自动测试、原生 uhttpd / rpcd 和浏览器验证的范围见 [VALIDATION.md](./VALIDATION.md)。

运行概况维护回归（Linux，已初始化固定子模块并具备 Go/Clang 构建环境）：

```sh
python3 openwrt/prepare-wing.py wing
(cd wing && go test -count=1 -v -tags daed_runtime_test ./dae ./graphql/service/general)
(cd wing/dae-core && go test -count=1 ./control -run 'Runtime|RelayTCP|Tracked|ActiveTCP')
```

`daed_runtime_test` 仅用于测试，正式构建不启用该标签。
